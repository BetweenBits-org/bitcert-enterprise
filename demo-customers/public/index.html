무역대금 국경간 정산 (VN→SG)

은행 시스템이 이미 만드는 SWIFT 전문을 그대로 넣으면 SDK가 지급지시로 바꿔 서명·제출하고, 결과는 SWIFT 상태코드와 pacs.002로 돌려줍니다. 수취측 화면은 :3300.

표본을 불러오면 매번 새 참조번호(UETR·전문번호)로 채워집니다. 같은 전문을 다시 넣으면 같은 지급으로 인식해 새로 만들지 않습니다.

레버: *.13 반환 · *.01 확정 보류 · ≥20000 수취측 추가정보 요청

이 탭이 쓰는 것

  • @stonehash/attest-remit — RemitClient.submitSwift() 전문 → 지급지시
  • commandSigner() — 은행 HSM 서명 (개인키는 HSM 밖으로 나오지 않음)
  • POST /v1/quotes · POST /v1/settlements · 상태 추적
  • swiftStatus() · statusReport() — 상태를 SWIFT 형식(pacs.002)으로
  • verifyEvidencePackage() — 커밋·서명·6축·앵커 재검증
가상의 고객사 포털입니다 — 세 회사 모두 합성 데이터이며, 연동 코드는 공개 API·SDK만 사용합니다. 은행 탭의 지급은 샌드박스 콘솔 계정 ops@demo-bank.example의 송금 원장에 그대로 보입니다. 심사·추가정보 응답·일별 대사까지 포함한 은행 업무 전체 데모는 데모은행(:3200)에, 같은 은행을 Java SDK로 연동한 데모는 Java 백엔드 데모(:3500)에 있습니다.
