무역대금 국경간 정산 (VN→SG)

버튼을 누르면 이 페이지 뒤의 Java 프로세스가 SDK를 호출합니다 — 전문 판독, 견적, 서명, 제출, 추적, 증빙 재확인이 모두 은행 쪽 Java 코드에서 일어납니다.

표본을 불러오면 매번 새 참조번호(UETR·전문번호)로 채워집니다. 같은 전문을 다시 넣으면 같은 지급으로 인식해 새로 만들지 않습니다.

버튼 뒤에서 도는 Java 코드

// 은행 시스템이 쓴 전문 그대로 — 호출 한 번
SwiftSubmission sent = client.submitSwift(
    message, options);
Settlement settled = client.track(
    sent.paymentId());
// 결과는 지급 허브가 읽는 형식으로
String pacs002 = client.statusReport(
    sent.paymentId());
// 자체 데이터로 — SDK 호출 다섯 번
Quote quote = client.quote(amount);
Instruction ins = client.buildInstruction(
    quote, parties, options);
client.submit(ins);
Settlement settled = client.track(
    ins.paymentId());
EvidenceReport report = EvidenceVerifier
    .verify(client.evidence(ins.paymentId()));
  • stonehash-attest-remit (Java 11+, 외부 의존성 없음)
  • Signers.external() — 은행 HSM 서명, 개인키는 JVM에 들어오지 않음
  • POST /v1/quotes · POST /v1/settlements · 상태 추적
가상의 은행입니다 — 합성 데이터이며, 연동 코드는 공개 API와 Java SDK만 사용합니다. 여기서 낸 지급은 샌드박스 콘솔 계정 ops@demo-bank.example의 송금 원장에 그대로 보입니다. 같은 은행의 TypeScript SDK 데모는 고객사이트 데모(:3400)에 있습니다.
