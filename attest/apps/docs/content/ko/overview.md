# 개요

StoneHash Attest는 기록을 해시하고, 그 해시를 비트코인에 커밋하며, 보유자에게는
저희에게 연락하지 않고도 누구나 확인할 수 있는 증명 파일을 건넵니다. 이 페이지는
지도입니다 — 이 서비스가 무엇을 증명하는지, 세 상품과 각 가이드의 위치, 지금
어느 환경에 있는지, 호출은 어떻게 인증되는지.

송금을 연동하려는 은행이라면 [국경간 송금](#corridor)에서 바로 시작하십시오.
귀행 시스템의 소스에서 SDK를 호출하며, 지급 시스템이 이미 만드는 MT103·ISO 20022
전문을 그대로 넘기면 서명된 지급지시가 됩니다.

## 무엇을 증명하는가

- **앵커링은 해시를 보내고, 문서는 보내지 않습니다.** 기록은 귀사의 기기에서
  해시하고 그 SHA-256 해시값을 제출합니다. 문서 자체를 받는 경로는 원본을 공개 비트코인
  트랜잭션에 싣는 명시적인 원본 전송 옵션 하나뿐입니다 — [보안과 프라이버시](#security)를
  보십시오.
- **증명 파일은 그 자체로 완결됩니다.** 이 파일과 비트코인을 들여다볼 수 있는 아무
  수단만 있으면, 누구든 StoneHash에 연락하지 않고 기록을 확인할 수 있습니다. 무료
  구간 기록은 `/v1/meta` 가 알려 주는 보존 기간이 지나면 사라지지만, 귀사가 API 키나
  콘솔로 만든 기록은 보존 기한 없이 삭제를 요청하실 때까지 보관됩니다. 내려받은
  파일은 어느 쪽이든 계속 검증됩니다.
- **수학적 검증은 오프라인에서 끝납니다.** 문서 일치, 묶음 포함, 트랜잭션 결합은
  네트워크 없이, StoneHash를 신뢰하지 않고도 검증됩니다.
  **체인 포함 여부의 확인은 귀사의 몫입니다** — 원하는 비트코인 소스로 확인하십시오.
  그 전까지 결과는 `skip`, 즉 "미확인"이지 "이상 없음"이 아닙니다.

## 세 가지 상품

| 상품 | 누구를 위한 것 | 시작하기 |
|---|---|---|
| **Attest Core** | 문서·기록을 비트코인에 증빙하려는 기업 | [빠른 시작](#quickstart), 기록에 귀사의 서명을 싣는다면 [발행인 서명](#signing) |
| **국경간 송금** | 스테이블코인 정산을 쓰는 은행·송금사업자 | [국경간 송금](#corridor) — 귀행 시스템 소스에 넣는 은행 SDK. 시스템이 이미 만드는 MT103·ISO 20022 전문을 그대로 넘기면 서명된 지급지시가 됩니다 |
| **Proof of Reserves**(준비금 증명) | 준비금 증명을 정기 발행하는 거래소 | [준비금 증명](#por) — 거래소 SDK와 공개 검증 페이지 |

송금·준비금 증명이 발행하는 앵커는 해당 상품 가격에 포함되어 Attest 쿼터를 쓰지
않습니다. 상품은 [샌드박스 콘솔](../console/)의 **구독**에서 활성화하며, API 키와
서명키도 그곳에서 관리합니다.

## 환경

샌드박스와 운영은 같은 요청 처리 코드로 돕니다. 차이는 어느 데이터베이스를 열고,
어느 앵커 백엔드를 구성하며, 어떤 키 접두사로 인증하는지, 그리고 샌드박스에만 있는
편의 — 셀프서브 콘솔과 터미널 키 발급 — 입니다. 지금 어느 배포와 이야기하고 있는지는
`GET /v1/meta` 가 알려 줍니다.

이 샌드박스는 비공개 **regtest** 체인에 앵커링합니다. 증명의 수학적 검증은 여기서도
mainnet과 똑같이 되지만, 체인 포함 여부는 제3자가 확인할 수 없습니다. 블록을 저희가
채굴하기 때문입니다. regtest 증명은 파이프라인 전 구간을 그대로 재현하지만 공개적으로
검증 가능한 증명은 아닙니다. 상용 배포는 공개 비트코인에 앵커링하며, 접근은 저희와
협의해 열립니다. 지금 쓰시는 콘솔은 샌드박스 전용입니다.

## 인증

| 단계 | 경로 | 방법 |
|---|---|---|
| **키 없음** | `GET /v1/meta`, 무료 구간(`POST /v1/public/anchors`), `POST /v1/sandbox/keys` | 아무것도 필요 없습니다. 무료 구간은 주소당·서비스 전체로 상한이 있고, 넘으면 `retry-after` 헤더와 함께 `429` 를 돌려줍니다. |
| **Bearer 키** | `/v1/attestations`, `/v1/settlements`, `/v1/por`, `/v1/issuer-keys` 등 키 기반 API 전체 | 샌드박스는 `Authorization: Bearer sk_test_…`, 운영은 `sk_live_…` — 접두사가 키의 일부입니다. 콘솔의 **연동 → API 키**에서 발급하거나, 터미널의 `POST /v1/sandbox/keys` 로 새 샌드박스 조직과 그 첫 키를 만듭니다. 한 번만 표시되고 해시만 저장되며, 여러 개를 라벨과 함께 동시에 둘 수 있습니다. |
| **콘솔 세션** | `/v1/console/*` | 콘솔 자체의 쿠키, 샌드박스 전용. 샌드박스에서는 키 기반 경로도 이 세션을 받아들여 콘솔이 귀사가 연동하는 바로 그 경로를 호출합니다. `/v1/console/*` 는 쿠키만 받습니다. |

서명키는 API 키가 아닙니다. 개인키는 귀사에 남고 공개키만 등록되어 상품을 활성화할
때 선택하는 ES256 키 쌍입니다 — [발행인 서명](#signing)을 보십시오. [API 레퍼런스](#api)는
한국어로도 읽을 수 있습니다 — 경로·필드·오류 코드·예시는 하나뿐이고, 설명만 같은 파일 안에
영문과 나란히 번역해 둡니다. [증빙 규격](#spec)은 일부러 영문만 제공합니다. 구현이
그대로 맞춰야 하는 계약이라, 번역본은 두 번째 정본이 되기 때문입니다.
